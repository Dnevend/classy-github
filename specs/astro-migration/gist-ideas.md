# Gist 分类方案与玩法建议

> 日期：2026-11-15　对应需求 9 / 10

---

## 9. 现有规则 `classy.category.title` 的问题

现在的约定是：Gist 描述写 `classy.blog.我的标题`，解析出分类和标题。它有两个隐藏成本：

1. **描述被规则吃掉**。Gist 描述本来是写摘要的地方，现在被当成元数据；
2. **表达力封顶**。不能有标签、日期、置顶、系列顺序，也不能一条 Gist 属于多个分类。

### 方案 A：描述里用 hashtag（最小改动，向后兼容）

```
classy.blog.我的标题 #长文 #AI
```

- 解析：前缀段保持，`#tag` 提取为标签从标题里剥掉；
- 好处：一条 Gist 可多标签、老数据完全兼容；
- 成本：~30 行解析 + 分类页加标签筛选。

### 方案 B：`_index` Gist 当清单（推荐）

建一条固定 Gist（比如 `classy.index`），里面是一份 front-matter 形式的清单：

```yaml
articles:
  - id: 9ec0af30…
    title: 用 Astro 重写 ClassyGit
    category: blog
    tags: [astro, cloudflare]
    date: 2025-11-02
    featured: true
```

- 好处：标题/分类/标签/顺序/置顶全部集中管理，正文继续用 Gist 写；
  一次请求拿到全部元数据，列表页不用拉每条 Gist 的描述；
- 成本：多一次 API 调用（缓存 10 分钟），用户要维护一个清单文件；
- 风险：清单和实际 Gist 可能不同步（可以只把清单当「排序+精选」，其余 Gist 仍按描述规则兜底）。

### 方案 C：Gist 文件名当 slug

`posts/astro-rewrite.md` —— 文件名即 slug，目录即分类。

- 好处：语义清晰，URL 稳定（`/u/gist/astro-rewrite`）；
- 代价：Gist 不支持目录（用 `slug--category.md` 这种伪目录），体验一般。

**建议**：先做 A（30 行，立刻可用），把 B 作为「进阶玩法」写进文档。
C 不推荐 —— Gist 的文件名不是为组织设计的。

## 10. Gist 还能怎么玩

按「投入 / 惊喜」排序，前四个性价比最高：

### 1. 文章级排版 + 阅读时间

给 `/gist/:id` 加正文排版（Tufte 式）、阅读进度条、估算阅读时长（中英分别按字数算）。
成本低，立刻让 Gist 从「代码片段」变成「能读的东西」。

### 2. RSS / Atom

`/u/rss.xml` 输出全部文章。**这是博客存在的意义**——订阅比算法推荐更可靠。
实现：复用列表数据 + 一个 XML 模板，30 行。

### 3. 系列 / 合集

用标签前缀 `series:xxx` 表示系列，文章页底部自动列出同系列其它文章（带序号）。
配 A 方案的标签解析即可，几乎零额外成本。

### 4. 目录 / 归档页

按年-月归档（`/u/archive`），带每月的条目数和标签云。
现在的 `/gists` 是平铺列表，文章多了就不可用。

### 5. Gist 评论聚合

用 GitHub 的 gist comments API 在文章页展示评论（只读）。Gist 本身支持评论，
用户不用注册新账号就能讨论。成本：一次 API + 渲染。

### 6. 代码片段「在线运行」

对 `code` 分类的 Gist，如果是 JS/TS，用 `<iframe srcdoc>` 或浏览器内 Babel/ESBuild-WASM 运行。
好玩但重（WASM 体积大），建议只对明确标记 `#runnable` 的 Gist 开启。

### 7. 变更历史 / diff

Gist 有完整的 revision 历史。文章页加一个「历史版本」抽屉，展示每次修改的 diff。
对技术笔记特别有价值（能看出结论是怎么演化的）。

### 8. `now` 页面

一条固定 Gist（`classy.now`）渲染成「我最近在做什么」，首页侧栏展示摘要。
比 bio 更有时间感，维护成本极低。

### 9. 输出成合集书

把某个分类下的所有文章按序拼成一篇长文 / 导出 Markdown 或 PDF。
适合「系列文章」，也是很好的分享物。

### 10. 与分享卡片打通

文章卡片自动带标题 + 摘要 + 二维码（已经有了），再加一个「引用此段」的锚点复制。

---

## 建议的落地顺序

1. **RSS**（30 行，价值最高）
2. **标签解析 A**（30 行，解锁筛选与系列）
3. **归档页**（半天）
4. **阅读时间 + 文章排版**（半天）
5. 系列 / 合集（依赖 2）
6. 评论聚合（可选）
